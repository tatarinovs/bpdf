# bpdf — Быстрая и легкая утилита для работы с PDF и документами

[![Версия](https://img.shields.io/badge/Версия-0.7.0-blue.svg)](Cargo.toml)
[![Rust](https://img.shields.io/badge/Rust-1.89%2B-orange.svg?logo=rust)](https://www.rust-lang.org/)
[![Платформа](https://img.shields.io/badge/Платформа-Windows-blue.svg?logo=windows)]()
[![Language](https://img.shields.io/badge/Language-English-blue.svg)](README.en.md)

**bpdf** — это консольный инструмент (CLI) на языке Rust для комплексной обработки PDF-файлов, изображений, текстовых документов и файлов Microsoft Office (Word, Excel, PowerPoint). Утилита ориентирована на высокую скорость, минимальный размер, надежность операций (атомарная запись) и гибкую автоматизацию (поддержка NDJSON, списков файлов и переменных окружения).

---

## Возможности

- **Объединение (Merge):** Склеивание PDF, обычных изображений, комиксов (CBZ), JPEG 2000/JPEG-LS/JPEG XR, HEIC/AVIF/PSD, RAW-снимков камер, электронных книг (EPUB, FB2, FB2.ZIP, HTMLZ), HTML-страниц, документов Word/Excel/PowerPoint/OpenDocument и текстовых файлов в единый PDF или текстовый файл.
- **Многостраничные изображения и комиксы:** Все страницы TIFF, архивы CBZ (с естественной сортировкой страниц) и все кадры GIF/APNG/анимированного WebP становятся отдельными страницами PDF при `merge`.
- **Распознавание текста (OCR) и создание Searchable PDF:** Извлечение текста со сканов, картинок и PDF в Markdown или создание PDF с невидимым текстовым слоем (`-o searchable.pdf`) через облачный **Groq Vision** (Qwen / Llama) или нативный локальный **Windows Media OCR** (без API-ключей и интернета).
- **Оглавление и закладки (Bookmarks):** Автоматическое построение дерева закладок PDF Outlines при объединении файлов (`merge --bookmarks`).
- **Умное кеширование OCR:** Content-addressed кеш на диске (SHA-256 хэш изображения + модель/движок + промпт). Повторные вызовы и параллельные потоки выполняются мгновенно без обращения к сети.
- **Поддержка сетевых прокси:** Работа через HTTP и SOCKS5 прокси для обхода блокировок или корпоративных ограничений.
- **Печати и штампы:** Наложение прозрачных PNG (или JPEG) изображений с точной позиционировкой (`br`, `center`, координаты в мм) или мышью (`--pick`), настройкой масштаба, прозрачности и режима смешивания (`multiply`).
- **Форматирование и приведение страниц:** Приведение к стандартам A4/Letter, центрирование содержимого, единая ориентация по большинству страниц и сохранение исходных размеров страниц PDF (`keep`).
- **Очистка метаданных (Strip):** Удаление EXIF-метаданных из JPEG/PNG без перекодирования пикселей, очистка свойств, XMP и EXIF встроенных картинок в PDF.
- **Редактирование PDF:** Разбиение на страницы (`split`), извлечение диапазонов (`extract`), поворот (`rotate`), изменение размера (`resize`), оптимизация структуры и изображений по DPI (`optimize`), в том числе с подгонкой под заданный размер файла (`--max-size`).
- **Нумерация и водяные знаки:** Номера страниц по шаблону (`number`) и текстовые водяные знаки вроде «КОПИЯ» (`watermark`); текст остаётся горизонтальным и на повёрнутых страницах.
- **Фотографии с телефона:** Ориентация из EXIF учитывается при сборке PDF, конвертации и OCR; снимки не ложатся набок.
- **Скорость:** Файлы в пакетных командах и картинки внутри PDF обрабатываются параллельно на всех ядрах (до 8 потоков).
- **Безопасное изменение in-place:** Атомарная запись через временный файл; правила перезаписи исходников описаны в разделе [Правила перезаписи файлов](#правила-перезаписи-файлов-in-place).
- **Информация и свойства PDF:** Размеры и повороты страниц, шрифты, картинки и свойства документа (`info`); изменение Title, Author, Subject, Keywords, Creator (`metadata`).
- **Диагностика (`doctor`):** Проверка конфигурации, доступности внешних утилит (`ffmpeg`, `powershell`, MS Office, браузер для HTML) и проверка API Groq без расхода лимитов OCR.
- **Автоматизация и Total Commander:** Полная оптимизация для работы с **Total Commander** (готовая панель кнопок `bpdf.bar`, встроенные иконки под каждое действие, поддержка списков файлов `@"%UL"` и `%P%N`). Поддержка тихих пакетных скриптов (`--quiet`), потокового вывода NDJSON (`--json`), шаблонов (globs `*.jpg`), естественной сортировки (`scan_1.jpg`, `scan_2.jpg`, `scan_10.jpg`) и файловых манифестов (`@list.txt`).

## Требования и внешние зависимости

- **ОС:** Windows 10 / 11 (x64) или Linux / macOS.
- **Внешние форматы изображений:** Для HEIC/HEIF, AVIF, PSD, JPEG 2000/JPEG-LS, DDS, EXR, HDR, QOI, TGA, PCX, PNM, SGI, XBM, DPX, FITS и других редких растров требуется установленный `ffmpeg` в системном `PATH` либо путь `ffmpeg` в `config.toml`. Фактический набор декодеров зависит от сборки FFmpeg.
- **Системные форматы Windows:** JPEG XR/HD Photo (`.jxr`, `.wdp`, `.hdp`) и ICO декодируются через встроенные кодеки Windows Imaging Component.
- **RAW-снимки камер:** По умолчанию снимки `.cr2`, `.cr3`, `.nef`, `.arw`, `.dng`, `.raf`, `.orf`, `.rw2` и другие мгновенно обрабатываются в **Pure Rust** путём извлечения полноразмерного встроенного превью от процессора камеры (кроссплатформенно: Windows, Linux, macOS). Полная проявка сенсора через Windows Imaging Component включается опцией `raw_develop = true` в `config.toml` (требует Microsoft Raw Image Extension: `winget install --id 9NCTDW2W1BH8 -s msstore`).
- **Конвертация Office/OpenDocument:** Для точного рендеринга DOC/DOCX/RTF/ODT, XLS/XLSX/ODS и PPT/PPTX/PPS/PPSX/ODP в Windows используется MS Office через COM-автоматизацию. Если MS Office не установлен или запуск на Linux/macOS, автоматически срабатывает встроенный **Pure-Rust fallback**, который извлекает форматированный текст и заглавия из XML-структур документов без сторонних зависимостей.
- **HTML-страницы:** `.html`, `.htm`, `.xhtml` вёрстаются headless-браузером на движке Chromium (Microsoft Edge есть в любой Windows 10/11; также подходят Chrome и Chromium) — со стилями, картинками и JavaScript, текст в PDF остаётся выделяемым. Если браузер не найден, срабатывает fallback: из страницы извлекается текст (без скриптов и стилей) и рендерится как текстовый PDF.
- **Groq Vision OCR:** Groq API Key требуется только для распознавания изображений; извлечение готового текстового слоя PDF работает без ключа. Ключ задаётся в `config.toml`, в том числе через `%GROQ_API_KEY%`.

## Сборка и установка

### Сборка через Cargo

```powershell
cargo build --release
cargo test --all-targets
```

На Windows сборка не требует C/C++ компилятора (TLS — системный SChannel). На Linux/macOS для TLS используется `rustls` с `ring`, которому нужен C-компилятор (`cc`/`clang`).

### Готовая сборка под Windows (релизный скрипт)

Для создания оптимизированного EXE со встроенными ресурсами Windows (иконка, манифест длинных путей, версии):

```powershell
.\build.bat
```

Скрипт выполнит:
1. Подготовку и проверку многослойной иконки (16x16 – 256x256 px; готовые ресурсы переиспользуются).
2. Считывание версии из `Cargo.toml`.
3. Компиляцию манифеста, версии и иконки через `rc.exe` (Windows SDK).
4. Оптимизированную сборку `cargo build --release --locked`.
5. Упаковку бинарного файла, файла конфигурации и документации в директорию `dist`.

## Глобальные флаги

Глобальные ключи могут передаваться перед любой подкомандой:

- `--config <PATH>` — Путь к файлу конфигурации (по умолчанию `config.toml` рядом с `bpdf.exe`).
- `--quiet` — Тихий режим. Подавляет вывод прогресса и информационных сообщений (конфликтует с `--json`).
- `--json` — Потоковый режим вывода NDJSON (выводит события и результаты в формате JSON, по одному объекту на строку).
- `--fail-fast` — Остановить пакетную команду после первой ошибки. Без этого флага остальные файлы обрабатываются, выводится итоговая сводка, а при наличии ошибок процесс завершается с ненулевым кодом.
- `-h, --help` — Вывести справочную информацию.
- `-V, --version` — Вывести версию программы.

## Команды и параметры

### Куда пишется результат

Команды, которые меняют файл (`strip`, `rotate`, `resize`, `optimize`, `stamp`, `number`, `watermark`, `metadata`), ведут себя одинаково:
- без ключей — рядом создаётся `<имя>_<действие>.<расширение>` (`doc_stamped.pdf`, `photo_rotated.jpg`);
- `-o <ФАЙЛ>` — запись в указанный файл (только для одного входа);
- `-o <ПАПКА>` — запись в существующую папку под исходными именами (для нескольких входов);
- `-i, --in-place` — перезапись исходного файла.

### 1. `bpdf merge`
Объединяет PDF, изображения, документы Office, HTML, книги и текстовые файлы в один PDF.

```powershell
bpdf merge <INPUTS>... [OPTIONS]
```

**Параметры:**
- `<INPUTS>...` — Входные файлы, папки, маски (`*.jpg`), диапазоны (`doc.pdf:1-5`) или списки (`@list.txt`). *(Обязательный)*.
- `-o, --out <PATH>` — Выходной файл. Без него: для одного файла `<имя>.pdf`, иначе `<первый>_merged.pdf`; существующие файлы не перезаписываются — берётся следующее свободное имя (`_merged_2.pdf`).
- `-s, --size <SIZE>` — Размер страниц: `A4`, `Letter` или `keep` (не менять размеры страниц входных PDF). По умолчанию — `page_size` из конфигурации.
- `--auto-rotate` / `--no-auto-rotate` — Повернуть страницы к ориентации большинства (при равенстве — как первая страница). По умолчанию — `auto_rotate`.
- `--optimize` / `--no-optimize` — Уменьшить картинки до `image_dpi` и сжать структуру. По умолчанию — `optimize`.
- `--strip-meta` / `--no-strip-meta` — Удалить метаданные из результата. По умолчанию — `strip_metadata`.
- `--bookmarks` / `--no-bookmarks` — Закладка на каждый объединяемый файл. По умолчанию — `bookmarks`.
- `--max-size <SIZE>` — Максимальный размер PDF (`10MB`, `500KB`, `1.5МБ`): разрешение и качество картинок понижаются ступенями, пока файл не уложится; если не получается, файл не создаётся и выводится достижимый минимум.

Каждая страница сохраняет свою ориентацию при приведении к A4/Letter. Автор и программа-создатель берутся из `author`/`creator` конфигурации; печать ставится отдельной командой `stamp`.

### 2. `bpdf ocr`
Распознаёт текст сканов и изображений через облачный Groq Vision или локальный Windows OCR. Для PDF решение принимается по каждой странице: страницы с собственным текстом берутся как есть, распознаются только страницы-сканы.

```powershell
bpdf ocr <INPUTS>... [OPTIONS]
```

**Параметры:**
- `<INPUTS>...` — Изображения, PDF (в том числе `doc.pdf:1-5`), папки или маски.
- `-o, --out <PATH>` — Общий результат:
  - `.pdf` — **Searchable PDF** с невидимым текстовым слоем;
  - другое расширение (например, `all.md`) — один Markdown-файл по всем входам;
  - без `-o` — `.md` рядом с каждым входом (совпадающие имена получают `_2`, `_3`).
- `-i, --in-place` — Добавить текстовый слой прямо в исходные PDF.
- `-e, --engine <ENGINE>` — `groq`, `windows` или `auto` (по умолчанию `ocr_engine`).
- `--lang <LANG>` — Язык Windows OCR (`ru`, `en-US`; по умолчанию `ocr_lang`).
- `--force-ocr` — Распознавать и страницы, у которых уже есть текстовый слой.
- `--no-cache` — Не использовать кеш OCR.
- `--clear-cache` — Очистить кеш OCR (можно без входных файлов).

Модель, промпт, прокси, адрес API и число параллельных запросов задаются в конфигурации. Текстовый слой ложится и на повёрнутые и обрезанные страницы; повторный `ocr -i` не дублирует слой, добавленный bpdf.

### 3. `bpdf split`
Разбивает PDF на одностраничные файлы `<имя>_01.pdf`, `<имя>_02.pdf`, …

```powershell
bpdf split <INPUT> [-o <DIR>]
```

- `-o, --out <DIR>` — Папка для страниц (по умолчанию — папка исходного файла).

### 4. `bpdf extract`
Извлекает выбранные страницы в новый PDF.

```powershell
bpdf extract <INPUT> <PAGES> [-o <OUT>]
```

- `<PAGES>` — Страницы в нужном порядке, с повторами: `5,1-4` переставляет, `1,1` дублирует, `reverse` разворачивает (синтаксис ниже).
- `-o, --out <PATH>` — Новый файл (по умолчанию `<имя>_extracted.pdf`); не может совпадать с исходным.

### 5. `bpdf info`
Показывает версию PDF, размер (pt и мм), поворот, число шрифтов и картинок каждой страницы, а также свойства документа (Title, Author, Producer, даты, наличие XMP).

```powershell
bpdf info <INPUT>
```

### 6. `bpdf text`
Извлекает существующий текстовый слой PDF без сети. Если слоя нет, предупреждает и предлагает `ocr`.

```powershell
bpdf text <INPUT> [-o <OUT>]
```

### 7. `bpdf strip`
Удаляет метаданные из JPEG, PNG и PDF без перекодирования пикселей. Неподдерживаемые файлы пропускаются.

```powershell
bpdf strip <INPUTS>... [-o <OUT> | -i]
```

В PDF удаляются свойства документа, XMP-пакеты и данные приложений у всех объектов, идентификатор `/ID` (если файл не зашифрован), а у встроенных JPEG — EXIF/XMP (в том числе GPS). Цветовые профили ICC сохраняются, если `keep_icc = true`.

### 8. `bpdf rotate`
Поворачивает страницы PDF или JPEG на угол, кратный 90°, либо к нужной ориентации.

```powershell
bpdf rotate <INPUTS>... -a <ANGLE> [-p <PAGES>] [-o <OUT> | -i]
```

- `-a, --angle <ANGLE>` — По часовой стрелке: `90`, `180`, `270`, `-90`; или `portrait` / `landscape` — повернуть только страницы другой ориентации.
- `-p, --pages <PAGES>` — Страницы PDF (по умолчанию `all`).

JPEG поворачивается **без потерь**: меняется тег ориентации EXIF, пиксели и остальные метаданные остаются как были (так же поступают просмотрщики Windows и телефоны). Перекодирование выполняется только в редком случае, когда в EXIF нет тега ориентации и его нельзя дописать.

### 9. `bpdf resize`
Вписывает видимую область страниц PDF в лист A4/Letter с центрированием (ориентация каждой страницы сохраняется, страницы нужного размера не трогаются) или меняет размер JPEG.

```powershell
bpdf resize <INPUTS>... [-s <SIZE>] [--long-edge <PX>] [--short-edge <PX>] [-p <PAGES>] [-o <OUT> | -i]
```

- `-s, --size <SIZE>` — Лист для PDF: `A4` (по умолчанию) или `Letter`.
- `--long-edge <PX>` — JPEG: длинная сторона не больше указанного.
- `--short-edge <PX>` — JPEG: короткая сторона ровно указанного размера.
- `-p, --pages <PAGES>` — Страницы PDF (по умолчанию `all`).

Для JPEG нужен `--long-edge` или `--short-edge`.

### 10. `bpdf optimize`
Сжимает структуру PDF и уменьшает картинки до `image_dpi` с качеством `jpeg_quality`. DPI считается по размеру, в котором картинка нарисована на странице (в том числе внутри форм): большое фото в маленькой рамке уменьшается до размера рамки. Если картинка встречается на нескольких страницах, берётся наибольший нужный размер. `image_dpi = 0` отключает уменьшение картинок.

```powershell
bpdf optimize <INPUT> [--max-size <SIZE>] [-o <OUT> | -i]
```

- `--max-size <SIZE>` — Уложить файл в размер (`10MB`, `500KB`): разрешение и качество понижаются ступенями от 300 DPI / 85 до 72 DPI / 35.

Фактически серые картинки (чёрно-белые сканы в RGB) сохраняются как одноканальные; картинка с цветной печатью или подписью остаётся цветной. Графика без потерь (диаграммы, чертежи, скриншоты — не больше 256 цветов) уменьшается, но остаётся без потерь, чтобы JPEG не размыл линии и текст.

### 11. `bpdf stamp`
Накладывает печать или штамп (PNG с прозрачностью или JPEG) поверх страниц.

```powershell
bpdf stamp <INPUT> <STAMP> [OPTIONS]
```

- `--position <POS>` — `br` (по умолчанию), `bl`, `tr`, `tl`, `c`, `tc`, `bc`, `l`, `r` или смещение `X,Y` в мм от правого нижнего угла (для отрицательных: `--position="-130,30"`).
- `--scale <SCALE>` — Множитель к физическому размеру; `0` — подобрать до четверти страницы.
- `--dpi <DPI>` — Разрешение изображения печати (по умолчанию из PNG/JPEG, иначе 96).
- `--opacity <0-1>` — Непрозрачность (по умолчанию `1`).
- `--blend <MODE>` — Смешивание: `normal`, `multiply` (реалистичные чернила поверх текста), `screen`, `overlay`, `darken` и др.
- `-p, --pages <PAGES>` — Страницы (по умолчанию `all`).
- `--pick` — Выбрать место мышью (см. ниже).
- `-o, --out` / `-i, --in-place` — Куда записать результат (по умолчанию `<имя>_stamped.pdf`).

Положение и размер считаются по видимой странице (CropBox, с учётом поворота). На сканах с iPhone/iPad, где лист A4 записан как огромная страница, размер и отступы пересчитываются под реальный лист.

**Интерактивная постановка (`--pick`).** Открывается окно Edge/Chrome со страницами документа. Печать перетаскивается мышью, размер меняется колесом или за уголки (с Shift — точнее), двойной клик ставит печать в точку. Можно листать страницы (PgUp/PgDn или миниатюры), ставить несколько печатей и копировать печать «на все страницы». Enter — применить, Esc или закрытие окна — выйти без изменений. Начальное положение берётся из `--position`, `--scale` и `--dpi`; по умолчанию печать появляется на последней странице, с `--pages` — на каждой выбранной. Внизу окна показаны эквивалентные `--position`, `--scale` и `--pages` (кнопка «Копировать»), чтобы потом ставить печать без окна.

**Примеры:**
```powershell
bpdf stamp "Договор.pdf" seal.png --pick --blend multiply -i
bpdf stamp "Доверенность.pdf" stamp.png --position="-130,30" --blend multiply -p last
```

### 12. `bpdf number`
Проставляет номера страниц; текст горизонтален и на повёрнутых страницах.

```powershell
bpdf number <INPUT> [OPTIONS]
```

- `--format <TEXT>` — Шаблон: `{n}` — номер, `{total}` — последний номер (по умолчанию `{n}`).
- `--start <N>` — Номер первой нумеруемой страницы (по умолчанию `1`).
- `-p, --pages <PAGES>` — Какие страницы нумеровать, например `2-last` без обложки (по умолчанию `all`).
- `--position <POS>` — Как у печати (по умолчанию `bc`).
- `--size <PT>` — Размер шрифта (по умолчанию `10`).
- `--color <COLOR>` — `black`, `gray`, `red`, `blue`, `green`, `white` или `#RRGGBB`.
- `--opacity <0-1>` — Непрозрачность (по умолчанию `1`).
- `-o, --out` / `-i, --in-place` — По умолчанию `<имя>_numbered.pdf`.

### 13. `bpdf watermark`
Текстовый водяной знак (например, «КОПИЯ») поверх страниц.

```powershell
bpdf watermark <INPUT> <TEXT> [OPTIONS]
```

- `--size <PT>` — Размер шрифта; `0` (по умолчанию) — подобрать под страницу.
- `--angle <DEG>` — Угол против часовой стрелки (по умолчанию `45`).
- `--position <POS>` — Позиция (по умолчанию `c`).
- `--color <COLOR>` — Цвет (по умолчанию `gray`).
- `--opacity <0-1>` — Непрозрачность (по умолчанию `0.3`).
- `-p, --pages <PAGES>` — Страницы (по умолчанию `all`).
- `-o, --out` / `-i, --in-place` — По умолчанию `<имя>_watermarked.pdf`.

```powershell
bpdf number report.pdf -p 2-last --format "Стр. {n} из {total}" -i
bpdf watermark contract.pdf "КОПИЯ" --color red --opacity 0.25
```

### 14. `bpdf metadata`
Задаёт свойства документа; неуказанные поля не меняются, пустое значение удаляет поле. Текущие значения показывает `bpdf info`.

```powershell
bpdf metadata <INPUT> [--title ..] [--author ..] [--subject ..] [--keywords ..] [--creator ..] [-o <OUT> | -i]
```

### 15. `bpdf convert`
Конвертирует изображения, PDF и HTML в JPEG.

- Многостраничный TIFF раскладывается на отдельные JPEG (`scan_page_1.jpg`, `scan_page_2.jpg`…); у анимаций (GIF, WebP) берётся первый кадр.
- Из PDF по умолчанию извлекается самая крупная картинка каждой страницы (JPEG — без перекодирования). Страницы со шрифтами и ключ `--render` дают рендер всей страницы (только Windows). Файлы называются `doc_page_3.jpg`; `--long-edge`, `--short-edge`, `--orient` и `-q` применяются и к ним.
- HTML снимается браузером в окне `html_viewport` (по умолчанию 1200×1600) после загрузки шрифтов и картинок.

```powershell
bpdf convert <INPUTS>... [OPTIONS]
```

- `-o, --out <DIR>` — Папка для JPEG.
- `--force` — Разрешить замену существующих файлов, включая исходник (`photo.jpg` → `photo.jpg`). Два входа, дающие одно имя, запрещены всегда.
- `--long-edge <PX>` / `--short-edge <PX>` — Размер по длинной/короткой стороне.
- `--orient <MODE>` — `landscape` или `portrait`.
- `-q, --quality <1-100>` — Качество JPEG (по умолчанию `jpeg_quality`).
- `--render` — Рендерить страницы PDF вместо извлечения картинок; учитывает `doc.pdf:2-4`.
- `--viewport <WxH>` — Окно браузера для HTML, например `1080x1080`.

### 16. `bpdf doctor`
Проверяет конфигурацию и внешние компоненты. Обязательное (шрифт, кеш OCR, выбранный движок OCR) даёт `FAIL` и ненулевой код возврата; отсутствие необязательного (FFmpeg, Office, браузер, неиспользуемый движок) — `WARN`. Ключ Groq проверяется запросом списка моделей без расхода лимитов OCR; ключи в выводе не показываются.

```powershell
bpdf doctor
```

## Форматы входа и селекторы страниц

### Форматы изображений

- Встроенный Rust-декодер используется для JPEG, PNG, BMP, GIF, WebP и APNG. TIFF на Windows декодируется через Windows Imaging Component, на остальных ОС — встроенным декодером. Для BMP/GIF/WebP/APNG при ошибке встроенного декодера автоматически пробуется FFmpeg.
- Текстовые файлы и FB2 читаются с учётом BOM и XML-декларации кодировки; файлы без неё, не являющиеся UTF-8, читаются как Windows-1251.
- Через FFmpeg (путь — `ffmpeg` в конфигурации) обрабатываются HEIC/HEIF, AVIF, PSD, JPEG 2000 (`.jp2`, `.j2k`, `.j2c`, `.jpc`, `.jpf`, `.jpx`), JPEG-LS (`.jls`), DDS, EXR, HDR, QOI, TGA, PCX, PNM (`.pnm`, `.ppm`, `.pgm`, `.pbm`, `.pam`), SGI, XBM, DPX, FITS (`.fits`, `.fit`, `.fts`), PGX, Sun Raster, XWD и PIX. Берётся первый видеопоток и первый кадр.
- Ориентация фотографий из EXIF учитывается: в PDF снимок встраивается без перекодирования и разворачивается матрицей отрисовки, при конвертации в JPEG сохраняется только тег ориентации (остальной EXIF удаляется), при перекодировании пиксели поворачиваются.
- Через встроенные кодеки Windows Imaging Component обрабатываются JPEG XR/HD Photo (`.jxr`, `.wdp`, `.hdp`) и ICO. Для ICO выбирается изображение с наибольшим разрешением.
- Снимки фотокамер `.3fr`, `.arw`, `.bay`, `.cr2`, `.cr3`, `.crw`, `.dcr`, `.dng`, `.erf`, `.fff`, `.gpr`, `.iiq`, `.k25`, `.kdc`, `.mef`, `.mos`, `.mrw`, `.nef`, `.nrw`, `.orf`, `.pef`, `.raf`, `.raw`, `.rw2`, `.rwl`, `.sr2`, `.srf`, `.srw` и `.x3f` по умолчанию декодируются в **Pure Rust** через извлечение полноразмерного JPEG-превью камеры. Полная проявка сенсора через WIC — `raw_develop = true` в `config.toml`.
- При `merge` все страницы TIFF и все кадры GIF/APNG/анимированного WebP добавляются в PDF по порядку (не более 10 000 кадров из одного файла). `convert` раскладывает многостраничный TIFF на отдельные JPEG, а для анимаций, как и `ocr`, берёт первый кадр.
- JPEG XL не заявлен как поддерживаемый: декодер JXL отсутствует во многих сборках FFmpeg.

### Электронные книги и текстовые форматы

- **Электронные книги:** `.epub`, `.fb2`, `.fb2.zip`, `.htmlz` (главы, заголовки и метаданные Title/Author). `.zip` распознаётся по содержимому: EPUB, FB2, HTMLZ или архив изображений (как `.cbz`).
- HTML: `.html`, `.htm`, `.xhtml` (через Edge/Chrome/Chromium, иначе — текст страницы). Относительные ссылки на CSS и картинки разрешаются от папки файла. Страница, которая помещается на лист пропорций `page_size`, становится одной PDF-страницей своего размера, длинная разбивается на листы её ширины; `@page { size }` страницы имеет приоритет. Затем страницы приводятся к `page_size`; `--size keep` оставляет размер вёрстки.
- Word: `.doc`, `.docx`, `.rtf`, `.odt`.
- Excel: `.xls`, `.xlsx`, `.ods`.
- PowerPoint: `.ppt`, `.pptx`, `.pps`, `.ppsx`, `.odp`.
- Текст: `.md`, `.txt`, `.json`, `.jsonc`, `.xml`, `.yaml`, `.yml`, `.log`, `.ini`, `.cfg`, `.csv`, `.tsv`, а также любые другие текстовые файлы и исходный код, определяемые по содержимому.
- Если все входы текстовые, по умолчанию они рендерятся в PDF. Выход с текстовым расширением (`-o result.txt`) объединяет их как обычный текст.

### Синтаксис диапазонов страниц
В ключах `-p/--pages`, в `extract` и прямо во входных путях (`doc.pdf:1-3` для `merge`, `ocr`, `convert`, `rotate`, `resize`):
- `all` — все страницы;
- `first` — первая страница;
- `last` (или `l`) — последняя страница;
- `even` — чётные страницы (2, 4, 6...);
- `odd` — нечётные страницы (1, 3, 5...);
- `reverse` — все страницы в обратном порядке;
- `1-5,8,last`, `2-last`, `5-` (с 5-й до конца), `5-1` (в обратном порядке) — комбинация страниц и диапазонов, в том числе со словами: `first,even`.

`extract` и выбор страниц во входе (`doc.pdf:3,1,2`) сохраняют указанный порядок и повторы; команды правки (`rotate`, `stamp`, `number` и др.) просто берут перечисленные страницы.

### Указание страниц прямо во входе
```powershell
bpdf merge scan.jpg report.pdf:1-3,last notes.txt -o result.pdf
```

### Списки файлов (Манифесты `@list.txt`)
Текстовый файл со списком входов передаётся с префиксом `@`:
```powershell
bpdf merge @files.txt -o output.pdf
```
Формат файла `files.txt`:
```text
# Комментарии игнорируются
C:\docs\cover.jpg
C:\docs\report.pdf:1-10
C:\docs\appendix.pdf:even
```

### Шаблоны (Globs) и директории
Маски (`*.png`, `scans/*.pdf`) раскрываются и сортируются в естественном порядке (`page1.jpg`, `page2.jpg`, `page10.jpg`). У каталога обрабатываются только файлы непосредственно в нём и только подходящие команде форматы.

### Интеграция с Total Commander
- **Готовая панель кнопок (`bpdf.bar`):** объединение, OCR, OCR на месте, очистка метаданных, разделение, извлечение страниц, информация о PDF, поворот, изменение размера, извлечение текста, оптимизация, печать, конвертация в JPEG, нумерация, водяной знак, свойства документа, `doctor`. Панель рассчитана на установку в `%COMMANDER_PATH%\tools\bpdf\`; для кнопки печати положите туда же `stamp.png`. Кнопки с параметрами перед запуском показывают командную строку для правки. Подписи кнопок — в кодировке windows-1251.
- **Списки выделенных файлов:** `@"%UL"` (список выделенных файлов в UTF-8 без ограничения длины командной строки) и одиночные файлы `%P%N`.
- **Встроенные иконки:** `bpdf.exe` содержит иконки для действий панели.
- `info` и `doctor`, запущенные из файлового менеджера, ждут Enter перед закрытием окна; при ошибке окно тоже не закрывается.

## Конфигурация (`config.toml`)

Файл ищется так:
1. путь из флага `--config <PATH>`;
2. `config.toml` в папке с `bpdf.exe`.

Текущий каталог не просматривается: Total Commander запускает bpdf в папке с документами, где может лежать `config.toml` другой программы. Неизвестный ключ (например, опечатка `jpeg_qualty`) — ошибка с именем ключа.

### Пример файла конфигурации

```toml
# API Ключ Groq для OCR
groq_api_key = "%GROQ_API_KEY%"

# Прокси-сервер (HTTP или SOCKS5)
proxy = ""
# proxy = "socks5://127.0.0.1:10808"

# Метаданные по умолчанию
author = "My Company"
creator = "bpdf toolkit"

# Параметры обработки PDF
auto_rotate = false
keep_icc = false
optimize = false
strip_metadata = false
bookmarks = false
page_size = "A4"
jpeg_quality = 95 # качество JPEG при merge и optimize
image_dpi = 150   # целевой DPI при merge и optimize; 0 отключает уменьшение
raw_develop = false # false = быстрое Pure-Rust превью, true = полная проявка WIC

# Настройки OCR
ocr_engine = "groq" # "groq" (облачный Vision), "windows" (локальный WinOCR) или "auto"
ocr_model = "qwen/qwen3.6-27b"
# ocr_prompt = '''Extract all text exactly as it appears...'''
ocr_endpoint = "https://api.groq.com/openai/v1/chat/completions"
ocr_jobs = 1
ocr_cache = true
# ocr_cache_dir = 'D:\cache\bpdf-ocr'
ocr_timeout_seconds = 120
ocr_max_tokens = 4096

# Пути к сторонним утилитам
# FFmpeg нужен для HEIC/HEIF, AVIF, PSD, JPEG 2000 и других внешних форматов
ffmpeg = 'ffmpeg'
powershell = 'powershell.exe'
# font_path = '%WINDIR%\Fonts\arial.ttf'
office_timeout_seconds = 120
# Браузер для HTML (по умолчанию ищутся Edge, Chrome, Chromium)
# browser = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
html_timeout_seconds = 60
html_viewport = "1200x1600" # размер окна для convert page.html
```

Полный образец с комментариями и всеми необязательными полями находится в [`config.example.toml`](config.example.toml).

В файле конфигурации поддерживаются подстановки переменных окружения в формате `%ИМЯ_ПЕРЕМЕННОЙ%` (например, `%GROQ_API_KEY%` или `%WINDIR%`), а также стандартные комментарии `#`. Для путей в Windows рекомендуется использовать одинарные кавычки `'...'` во избежание экранирования обратных слэшей.

## Примеры использования

```powershell
# Объединение изображений, отсканированного PDF и заметок в единый PDF
bpdf merge scan.jpg invoice.pdf:1-3 notes.txt -o result.pdf

# Объединение всех картинок из папки с приведением к A4 и автоповоротом
bpdf merge *.jpg -s A4 --auto-rotate --optimize -o scans.pdf

# Объединение с сохранением исходной ориентации каждой страницы
bpdf merge *.pdf -s A4 --no-auto-rotate -o mixed.pdf

# Печать в правый нижний угол с прозрачностью 60%
bpdf stamp invoice.pdf seal.png --opacity 0.6

# Печать с отступом 150 мм влево от правого нижнего угла
bpdf stamp invoice.pdf seal.png --position="-150,0" -i

# Распознавание текста со скана через Groq Vision в Markdown
bpdf ocr scan.jpg -o scan.md

# Searchable PDF прямо в исходных сканах локальным Windows OCR
bpdf ocr scans/*.pdf -e windows -i

# Конвертация AVIF и PSD в JPEG через FFmpeg
bpdf convert photo.avif design.psd --out converted

# Конвертация JPEG 2000, JPEG-LS, JPEG XR и ICO в JPEG
bpdf convert scan.jp2 medical.jls photo.jxr icon.ico --out converted

# Конвертация RAW-снимков фотоаппаратов в JPEG (быстрое превью без кодеков)
bpdf convert photo.cr3 photo.nef photo.arw --out converted

# Карточки товаров из HTML в JPEG 1200×1600 (все .html в папке)
bpdf convert cards --out jpg
bpdf convert banner.html --viewport 1080x1080 -q 90

# Все страницы TIFF и кадры анимации становятся страницами PDF
bpdf merge multipage.tiff animation.apng animation.webp -o pages.pdf

# PowerPoint и OpenDocument в PDF
bpdf merge slides.pptx report.odt table.ods -o office.pdf

# Сохранённая веб-страница в PDF (вёрстка через Edge/Chrome)
bpdf merge page.html -o page.pdf

# Конвертация электронных книг (EPUB, FB2, FB2.ZIP) в PDF
bpdf merge book.epub -o book.pdf
bpdf merge story.fb2.zip -o story.pdf

# JSON/XML/YAML как текстовый PDF
bpdf merge data.json settings.xml config.yaml -o data.pdf

# Наложение печати поверх документа с реалистичным смешиванием чернил (multiply)
bpdf stamp document.pdf stamp.png --position="-130,30" --blend multiply

# Очистка EXIF метаданных у всех фото в папке на месте
bpdf strip photos/*.jpg -i

# Разбиение PDF на отдельные страницы
bpdf split document.pdf -o output_pages/

# Извлечение первых 5 страниц и последней страницы
bpdf extract document.pdf 1-5,last -o selected.pdf

# Поворот всех четных страниц PDF на 90 градусов на месте
bpdf rotate document.pdf -a 90 -p even -i

# Приведение страниц PDF к формату Letter
bpdf resize document.pdf --size Letter

# Извлечение встроенного текстового слоя в файл
bpdf text document.pdf -o text_layer.txt

# Установка свойств документа PDF
bpdf metadata document.pdf --title "Отчет 2026" --author "Иван Иванов" -i

# Извлечение картинки/конвертация изображений в JPEG
bpdf convert photo.png document.pdf -o converted_jpegs/

# Проверка работоспособности системы и интеграций
bpdf doctor

# Интеграция со скриптами в режиме NDJSON
bpdf --json merge *.jpg -o result.pdf
```
